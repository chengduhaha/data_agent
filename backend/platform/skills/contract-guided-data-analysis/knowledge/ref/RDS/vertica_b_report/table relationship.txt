# Vertica B REPORT table relationships
#
# Country schemas are normalized with xx in this file.
#
# Scope
#   Generated from Vertica B REPORT rds_xxx_rtv.sp scripts identified by matching
#   Vertica *_gen.sp files that contain rdsetl.rds_tmp.
#   B REPORT scripts are identified by SELECT/FROM usage of
#   dwd_disty_common_dw_orders_pl_extend_di, dws_disty_brpt_pl_extend_mtd,
#   or dwd_disty_pub_dw_orders_extend_di.
#   Ignore UPDATE-only usage of those tables when choosing B REPORT examples.
#
# Common grain
#   PL order-line grain: order_no, order_type, order_line_no, date_flag.
#   PL daily/monthly sales grain: date_flag with optional customer, SKU, vendor, VPL, PM, territory, or division dimensions.
#   Monthly B REPORT PL summary grain: date_flag/month plus selected sales/product/customer/PM dimensions.
#   Customer grain: cust_no or mcust_no, depending on bill-to/customer versus master customer reporting.
#   Product grain: sku_no.
#   Vendor grain: vend_no.
#   VPL grain: vpl_no or dim_vpl_no.
#   Sales hierarchy grain: sales_terr.


# Core B REPORT PL and Order Relationships

dw_xx.dwd_disty_common_dw_orders_pl_extend_di is the primary B REPORT fact for PL order-line sales, margin, profit, vendor, customer, product, VPL, PM, and territory analysis.
dw_xx.dwd_disty_common_dw_orders_pl_extend_di should usually filter date_flag for the requested sales window before joining enrichment tables.
dw_xx.dwd_disty_common_dw_orders_pl_extend_di often filters shippable order types by joining dim_xx.dim_pub_order_type on order_type and requiring ship_tran_no is not null.

dw_xx.dwd_disty_common_dw_orders_pl_extend_di (many to one) ods_xx.ods_cis_corp_history_header by using join columns order_no, order_type when ODS order header fields are required; filter delete_date is null when present in the source report.

# Measures and Aggregation Grain

B REPORT sales measures commonly come from dw_xx.dwd_disty_common_dw_orders_pl_extend_di columns such as ship_qty, u_price, u_sum_expense, net_sales, gm_amt, tgm_amt, ngm_amt, oplgm_amt, infrastructure, hc_sales, hc_pm, hc_bd, order_overhead, marketing, scm_profit_adj, others, and corporate.
Net sales may be calculated as ship_qty * (u_price + COALESCE(u_sum_expense, 0)) when the report derives it manually instead of using net_sales.
GM, TGM, NGM, OPL, and percent metrics should be aggregated first, then divided with NULLIF on the denominator, for example sum(gm_amt) / nullif(sum(net_sales), 0).
NGM0-style metrics can subtract infrastructure, headcount, order overhead, marketing, SCM profit adjustment, others, and corporate from NGM before calculating percentages. Preserve the exact component list from the source report.
Use count(distinct order_no) for order-count metrics only after the final driving grain is clear; order-line-level joins can otherwise inflate counts.
Pre-aggregate PL facts to the requested grain before joining one-to-many profile, contact, serial number, EU custom, SCM/SPA, or recommendation tables.

Regional schemas such as dw_hyus, dw_hyuk, dw_hycn, dw_wcla, dw_us, dw_ca, and dw_ww are normalized to dw_xx for reference only. Generated SQL for a concrete report should use the target region schema required by the user.


# Output and Grain Notes

Use dw_xx.dwd_disty_common_dw_orders_pl_extend_di as the driving source when the report asks for sales, PL, margin, NGM/OPLGM/TGM/GM, customer/product/vendor/VPL profitability, territory performance, or order-line B REPORT detail.
Use dw_xx.dws_disty_brpt_pl_extend_mtd as the driving source when the report asks for month-to-date or monthly summarized B REPORT PL metrics.
Use dw_xx.dwd_disty_pub_dw_orders_extend_di when the report needs lightweight DW order extension fields and not the full PL/margin extension set.
Preserve report-specific date windows, order_type filters, sales territory filters, customer/vendor/SKU/VPL hardcoded lists, profile_type filters, and active/delete flags before adding new joins.
Prefer LEFT JOIN from PL fact rows to optional enrichment tables when the report must preserve shipped order-line rows.
Pre-aggregate or rank one-to-many enrichment tables before final output to avoid inflating order-line sales and margin amounts.
