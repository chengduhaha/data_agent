# Vertica OPEN_SO_BO table relationships
#
# Country schemas are normalized with xx in this file.
#
# Scope
#   Generated from Vertica OPEN_SO_BO rds_xxx_rtv.sp scripts identified by matching
#   Vertica *_gen.sp files that contain rdsetl.rds_tmp.
#   OPEN_SO_BO scripts are identified by SELECT/FROM usage of dwd_disty_sales_open_order_detail.
#   Use dw_xx.dwd_disty_sales_open_order_detail as the main open sales order / backorder detail source.
#
# Common grain
#   Open SO/BO line grain: order_no, order_type, order_line_no
#   Open SO/BO SKU grain: order_no, order_type, order_line_no, sku_no
#   Product grain: sku_no
#   Customer grain: cust_no or master_cust_no
#   Location grain: from_loc_no / to_loc_no / loc_no
#   CPO bridge grain: cpo_id / int_ref_no and cpo_line_seq / int_ref_line_no
#   SCM/SPA grain: order_no, order_type, order_line_no, scm_no/spa_no

dw_xx.dwd_disty_sales_open_order_detail (many to one) dim_xx.dim_pub_order_type by using join columns order_type
dw_xx.dwd_disty_sales_open_order_detail should filter order_delete_date is null and order_line_delete_date is null for active open-order reporting unless deleted lines are explicitly requested.
dw_xx.dwd_disty_sales_open_order_detail should filter order_line_type <> 'Comp' when component lines should be excluded from line-level backlog or shipment metrics.
dw_xx.dwd_disty_sales_open_order_detail should preserve report-specific filters on order_type, vend_no, cust_no, master_cust_no, sku_no, prod_code, from_loc_no, to_loc_no, order_status, ship_method, and requested/expected dates.

# Output and Grain Notes

Use LEFT JOIN from dw_xx.dwd_disty_sales_open_order_detail to optional enrichment tables such as product, location, manager, order profile, EU custom, CPO, ETA, SCM/SPA, carton, serial, inventory, and BTO/QC to preserve open order rows.
Use INNER JOIN only when the source report intentionally restricts to a vendor/customer/SKU list, required hierarchy, required part list, or required operational status.
Pre-aggregate, rank, or filter one-to-many enrichment tables before the final join when output grain must remain one row per open SO/BO line.
Apply date_flag/current snapshot filters to daily snapshot tables such as dw_xx.dwd_disty_brpt_bo_detail_df, dw_xx.dwd_disty_inv_qty_df, dw_xx.dwd_disty_inv_aging_df, dw_xx.dwd_disty_inv_aging_rollover_rtv2_df, and dm snapshot tables.
Keep report-specific filters in the earliest staging table so downstream joins stay small and optional relationships do not change the open backlog population.
