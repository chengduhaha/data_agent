# StarRocks OPEN_SO_BO table relationships
#
# Country schemas are normalized with xx in this file.
#
# Scope
#   Generated from StarRocks OPEN_SO_BO rds_xxx_rtv.sp scripts identified by matching
#   StarRocks *_gen.sp files that contain tempdb.rds_tmp.
#   OPEN_SO_BO scripts are identified by SELECT/FROM usage of dm_pur_unieta_boso_detail_rt
#   or order header sources with order_type = 1/8 and ship_date is null.
#   Use current order header/detail tables as the driving source for open SO/BO rows;
#   use dm_xx.dm_pur_unieta_boso_detail_rt when the report is ETA/backorder driven.
#
# Common grain
#   Open order header grain: order_no, order_type
#   Open order line grain: order_no, order_type, order_line_no
#   Open SO/BO SKU grain: order_no, order_type, order_line_no, sku_no
#   Product grain: sku_no
#   Customer grain: cust_no
#   ETA grain: order_no, order_type, order_line_no, sku_no

# Output and Grain Notes

Use LEFT JOIN from open SO/BO base rows to optional enrichment tables such as product, customer, location, manager, ETA, profile, EU custom, CPO, RIO, inventory, carton, serial, and shipment lookups to preserve open order rows.
Use INNER JOIN only when the source report intentionally restricts to a required customer/vendor/SKU list, required CPO/order chain, required ETA population, or required operational status.
Pre-aggregate, rank, or filter one-to-many enrichment tables before the final join when output grain must remain one row per order line.
Keep order_type, ship_date, delete_date, vendor, customer, location, SKU, ETA, and date_flag filters in the earliest staging table so downstream joins stay small and optional joins do not change the open SO/BO population.
